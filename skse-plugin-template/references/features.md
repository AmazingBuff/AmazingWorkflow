# Optional features

Only the minimal plugin is generated by default. Modules live in
templates/features and do not appear in an unselected generation result. The
reference relations are dependency relations, not a suggestion to "enable
everything". Select only the entry features the current functionality needs.

| Feature | Automatic dependencies | Files and purpose |
| --- | --- | --- |
| config | none | src/config; Setting + INI with example Enabled/Hotkey fields. |
| input | config | src/input; keyboard-event hotkeys, no Present or menu dependency. |
| menu | config | src/ui/ui_menu.*; optional MCP Enabled/Save settings page. |
| present_hook | none | src/render/present_hook.*; standalone REX PresentHook, does not install a callback automatically. |
| render | present_hook | src/render/renderer.*; explicitly selected Renderer/OverlayDirector extension point, no default drawing. |
| dx11 | none | src/render/dx11; CommonStates, D3D11StateCapture, compile_shader. |
| shaders | dx11 | ShaderManager, common HLSL, embed script, and cmake/shaders.cmake. |
| render_util | none | Color, coordinate transforms, and projection functions. |
| pulse_timer | none | Standalone PulseTimer; generates no trigger policy. |
| hash | none | Hash functions in src/base/def.h; generates no business calls. |

For example `--features input` outputs config and input; without menu, render,
or shaders. Only `--features menu` adds the SKSE-MCP submodule and link.
Choosing shaders generates the HLSL build steps. The low-level present_hook,
dx11, render_util, pulse_timer, and hash can be selected individually for
existing logic to call. render and shaders can be selected independently; the
actual drawing pass is wired in by the user and is not presented as a
ready-made feature.

## Package format

```text
templates/features/config/
  feature.json
  src/config/config.h
  src/config/config.cpp
templates/features/shaders/
  feature.json
  cmake/shaders.cmake
  cmake/embed_shaders.cmake
  src/render/shader_manager.h
  src/render/shader_manager.cpp
  src/render/shaders/overlay.hlsl
```

Content under src/ and cmake/ is merged into the output project by relative
path; feature.json itself is not copied into the project. Duplicate target
paths are rejected and never silently overwrite the base template or another
feature. Unknown features, duplicate selections, and dependency cycles error
out before writing. No network operation runs by default; only
--add-submodules fetches the actually selected submodules.

feature.json fields:

- description, requires: purpose and dependent features.
- includes: module headers used by main.cpp.
- ports, packages, link_libraries: complete vcpkg ports, find_package calls,
  and target links respectively.
- submodules: url/path pairs that populate both .gitmodules and
  add_subdirectory.
- cmake_includes, generated_sources: generated-file steps and the plugin
  target's generated inputs.
- on_load, on_data_loaded, on_game_ready, on_save: lifecycle calls that are
  actually needed.

When adding a feature, declare minimal dependencies; do not bind modules to
each other because they are often used together. Module headers include the
standard-library/API headers they need themselves, instead of relying on "the
header happens to exist when the full set is compiled together".

## Current adaptation behavior

config::Setting uses a locked snapshot and a toggle interface; load/save are
called at the game entry/SaveGame points; the example key is VK F7 (0x76), not
a scan code. When the configuration file does not exist the example defaults
are used, and saving creates the INI. input attempts idempotent registration
on the DataLoaded and game-ready messages and only handles keyboard IsDown;
when menu is selected alongside, it additionally checks Menu::is_menu_open —
without menu there is no such include/call. The menu only provides the already
wired Enabled/Save controls; it does not contain unimplemented rebind buttons.

render installs the Present callback idempotently at the same points;
present_hook preserves the original function and contains plugin callback
exceptions. shaders attempts compilation on DataLoaded; if the device is not
ready yet, the later actual consumer must call compile according to its device
lifecycle. The state capture's scope, device recreation, window resize,
events/threads, and runtime compatibility still need verification against the
new plugin's needs. Utility features do not gain business consumers
automatically and are not wired into the Renderer automatically.

## Manual reuse and verification

An existing project may copy only the files one feature needs, but the
manifest's build and lifecycle wiring points must be checked together; do not
use the generator as an upgrade command that overwrites an existing project.
Trimmed modules still follow reuse-guide.md.

Regression tests check the default minimal output, dependency completion, each
feature, all pairwise combinations, and the full set for file/include
consistency. The full set is actually compiled in Release; in-game behavior,
Debug/VR builds, and fresh dependency fetching are tracked separately as
verified or not.

Current verification status: default generation is still 12 files; 10
individual selections, 45 pairwise combinations, and the full set passed
generation checks. The full set was configured and compiled/linked as a DLL
with MSVC 19.44.35228 / Windows SDK 10.0.26100.0, reusing matched CommonLib
static libraries and an existing vcpkg cache. In-game runs, Debug/VR builds,
and fresh network dependency fetching were not verified.
