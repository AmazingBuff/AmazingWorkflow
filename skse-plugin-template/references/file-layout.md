# 文件编排：先有职责，再有目录

沿用参考工程“根构建文件 + cmake 生成材料 + src 按职责分组”的方式。
参考目录名用于举例，不是所有插件都必须拥有的目录。

## 最小项目

main.cpp 只负责入口、日志和必要初始化。pch.h 放稳定且广泛使用的基础头文件，
引入构建生成的 plugin.h。元数据来自根 CMake 的 PROJECT_NAME、PROJECT_VERSION、
PROJECT_NAMESPACE、PROJECT_AUTHOR；不要在多个模块复制项目名/版本字符串。

模块自己的头文件应表达可调用接口，cpp 保存实现和私有状态。项目代码放在
PLUGIN_NAMESPACE_BEGIN/END 内；SKSE 导出保留全局 C ABI。

## 何时新增文件

| 实际需求 | 建议位置 | 边界 |
| --- | --- | --- |
| 持久化设置 | src/config/config.h/.cpp | 只包含当前插件的配置字段及读写；其他模块通过明确接口使用。 |
| 游戏输入处理 | src/input/input.h/.cpp | 负责事件转换/按键处理，不承担渲染或 INI 实现。 |
| 设置界面 | src/ui/ | 负责界面和交互；使用配置接口，按选定 UI 库添加依赖。 |
| 渲染功能 | src/render/ | 对外入口、hook、shader 管理、具体 pass 按实际复杂度拆分。 |
| D3D 工具被多处使用 | src/render/dx11/ | 只放实际需要的设备/状态工具，不复制整个工具库。 |
| 一个事件或引擎 hook | 对应业务模块，必要时 src/events 或 src/hooks | 目录是否存在于参考工程不决定它是否合理。 |
| 多模块共享的小工具 | 靠近使用方，确有共享再放 src/base/ | 不为“以后可能用”提前加入 hash、计时器、投影等代码。 |

一个小功能不需要 facade/director/manager 各一层；出现独立责任或状态生命周期时才拆分。
没有渲染需求就不建立 render/shaders，也不放空的 draw()。

## 修改已有项目

先查看调用方和构建收集方式，再移动文件或修改接口。目录改名、include 路径、命名空间、
CMake 输入和测试应一次更新。不要为了让树形图像参考工程而重构无关代码。
原业务模块只在用户需求确实涉及该业务时引入。
