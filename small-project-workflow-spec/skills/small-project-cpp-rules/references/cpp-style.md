## 适配原则

先读取 `.clang-format`、`.clang-tidy`、`.editorconfig`、编译选项和相邻第一方代码。已有机器可执行规则优先；不要用本文件批量改写稳定旧代码。

以下默认值只用于绿地项目，或目标模块没有可识别约定时。

## 绿地命名默认值

| 对象 | 默认规则 | 示例 |
|---|---|---|
| 文件 | 小写 `snake_case` | `task_queue.h` |
| 类型、concept、枚举类型 | `PascalCase` | `TaskQueue`, `Serializable` |
| 函数、方法、局部变量 | `snake_case` | `enqueue_task`, `task_count` |
| 私有成员 | `m_` + `snake_case` | `m_task_count` |
| 枚举值 | `e_` + `snake_case` | `e_ready`, `e_count` |
| 宏 | `UPPER_SNAKE_CASE` | `LIBRARY_EXPORT` |
| 模板参数 | 简短类型名或语义名 | `T`, `Value`, `Allocator` |
| 常量 | 项目内统一的一种常量格式 | `Default_Timeout` |

- 第一方代码放入项目根命名空间；实现细节可放入 `Internal` 或项目既有的 detail 命名空间。
- 只有项目已定义命名空间宏时使用宏。
- 保留外部 ABI、框架 override、生成代码和协议要求的名称。
- 不通过作者名、创建日期或版权模板推断代码归属；仅在项目明确要求时添加文件头。

## 文件与 include

- 沿用项目已有扩展名；绿地默认使用 `.h` / `.cpp`，大型模板实现可使用 `.inl`。
- 每个头文件使用 include guard 或 `#pragma once`，在同一模块保持一致。
- include guard 从完整项目相对路径生成，避免不同目录同名头冲突。
- `.cpp` 的 include 顺序默认为：对应头、同项目头、第三方头、标准库头；组间空一行。
- 不使用父目录相对 include；从目标配置的 include 根引用。
- 公共头优先前向声明，避免暴露私有实现和不必要依赖。
- 预编译头只放稳定且广泛使用的头，不加入频繁变化的模块实现。

## 格式

- 使用项目格式化器；无配置时使用 4 空格、无 Tab、无行尾空格。
- 绿地默认使用 Allman 大括号，并在同一文件保持一致。
- 多语句控制流必须加大括号；单语句规则跟随局部风格。
- 访问区顺序默认 `public` → `protected` → `private`。
- 绿地默认使用 east const：`Type const&`、`Type const*`。
- 指针和引用符号跟随项目格式；无配置时写作 `Type* value`、`Type& value`。
- 不使用 `using namespace std;`。
- 不手工争论行宽；使用项目格式化器，或保持参数组和表达式可扫描。

## 类型与接口

- 多态接口使用虚析构，具体实现标记 `final`，重写标记 `override`。
- 能由编译器生成或禁止的特殊成员使用 `= default` / `= delete`。
- 不可忽略的结果使用 `[[nodiscard]]`；无抛出保证成立时使用 `noexcept`。
- 使用 `enum class`，并选择满足 ABI/协议的底层类型。
- 容量、索引和字节数优先使用适当的无符号尺寸类型；协议和持久化字段使用固定宽度整数。
- 优先 `nullptr`、named cast 和作用域枚举，避免 C 风格转换与无类型宏。
- 公共接口不泄漏具体后端、私有类型或外部库实现细节。

## 模板与复用

- 新模板约束优先使用 concepts/`requires` 和 `if constexpr`。
- forwarding reference 必须配合 `std::forward`，避免无意复制。
- 编译期类型策略使用 trait/policy；真实运行时替换使用接口或 callable。
- 先写最小通用核心，再让便利重载转发；不要复制算法主体。
- type erasure 明确 owned value 与 borrowed reference，并覆盖空状态和特殊成员。
- 不为单个调用点创建通用注册表、元编程框架或配置系统。

## 所有权

- 普通代码避免裸 `new` / `delete`，优先值语义、RAII 和唯一所有权。
- 裸指针/引用表达借用；拥有型句柄必须由 RAII wrapper 或成对 API 管理。
- 不默认使用 `shared_ptr`；先证明存在跨所有者的共享生命周期。
- 资源类明确复制、移动和析构语义；不可复制资源显式 `= delete`。
- 锁的所有权、线程亲和性和调用方同步责任必须可见。
- 尊重项目或框架已有所有权模型，不做机械智能指针替换。

## 错误与注释

- 内部不变量使用项目 assertion；输入或外部失败使用项目既有结果/异常模型。
- 对外部错误集中转换并补充操作和输入上下文。
- 检查不可忽略返回值，不用日志代替错误传播。
- 让命名和结构解释“做什么”，注释解释不变量、原因、单位、坐标、ABI、线程和生命周期限制。
- 代码变化后同步注释；不在无关修改中清除仍准确的历史说明。
- 复杂到需要逐行解释时，优先提取函数、类型或阶段。

## 禁止项

- `using namespace std;`。
- 父目录相对 include。
- 无必要的公共头依赖。
- 可 `= default` 却手写空特殊成员。
- 跨模块 `friend` 访问私有实现。
- 在公共 API 中泄漏具体适配器或外部库类型。
- 静默忽略失败、未初始化返回值或不成对的资源释放。
- 从 vendor、生成文件、构建产物或机械 API 表复制风格。
- 为符合本 skill 而批量重写未触及代码。
